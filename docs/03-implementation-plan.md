# 03 · 实施计划

## 1. 开发原则

1. **纵向切片**：每个里程碑都要能跑通一条完整路径，不做“先写完所有后端再写前端”。
2. **规则先写测试**：重叠、边界、提交日、租户隔离先有失败测试或验收用例，再写实现。
3. **seed 先行**：M0 就把演示账号和演示视频准备好，后面每次启动都能直接演示。
4. **文档同步**：决策变更先改 `01-decisions.md`；API 变更先改 `02-architecture.md`。
5. **不做范围外功能**：评论、AI 分段、多人协作、注册、URL 导入都不做，避免挤占核心闭环。

## 2. 里程碑

### M0 · 脚手架与一键启动

**目标**：空项目能启动，前后端和数据库都通。

任务：

- 创建目录结构、`.gitignore`、`.env.example`。
- `AGENTS.md`、`docs/` 定稿（含 06 UI、07 API、08 自审）。
- 初始化 git 仓库（只 init，不自动 commit）。
- `docker-compose.yml`：db、backend、frontend。
- 后端最小 FastAPI：`GET /api/health`。
- 前端最小 React 页面：显示服务状态。
- `README.md` 初稿：启动命令、演示账号。
- `scripts/generate_demo_video.py`：用 ffmpeg 生成 60 秒演示视频。

验收：

- `docker compose up --build` 后，`http://localhost:8080` 能打开。
- `GET /api/health` 返回 `{"status":"ok"}`。
- 演示视频生成成功，能被浏览器播放。
- 从干净目录按 README 能启动。

### M1 · 数据模型、认证与租户

**目标**：三种角色能登录，租户隔离的后端骨架成立。

任务：

- SQLAlchemy 模型：tenants、users、videos、tasks、assignments、segments。
- Alembic 初始迁移；部分唯一索引。
- seed：2 个租户、3 种角色、演示视频、不同状态的任务。
- seed 视频：用 M0 生成的 demo 文件，`ffprobe` 后写 `videos` 表并复制到 `storage/videos/{tenant}/`；不依赖上传接口。
- 创建项目 skills：`domain-review`、`api-contract`、`tenant-isolation-review`、`ux-review`、`release-check`；至少实际用于一次检查。
- 登录/登出/me；HttpOnly Cookie 会话；密码哈希；登录后重新生成 session。
- 角色依赖、租户依赖、越权 404 的统一处理。
- 基础测试：登录、me、角色权限、跨租户访问。

验收：

- 平台管理员、租户管理员、标注员都能登录。
- `me` 返回正确角色和租户。
- 租户管理员访问另一个租户的任务返回 404。
- seed 账号写入 README。
- 数据库重启后数据仍在。

### M2 · 视频上传、探测与 Range 播放

**目标**：管理员能上传视频，浏览器能播放和拖动。

任务：

- `POST /api/admin/videos` 流式上传，限制 2 GB。
- ffprobe 探测时长、fps、分辨率、编码；失败清理文件。
- 帧率优先 `avg_frame_rate`，回退 `r_frame_rate`；VFR/未知帧率时前端不吸附帧。
- 记录浏览器 `video.duration` 与服务端 `duration_ms` 的差异；> 1000 ms 时前端提示。
- faststart remux；可选 H.264 转码开关。
- 封面生成；`GET /poster`。
- `GET /api/videos/{id}/stream`：鉴权、租户/任务可见性、Range 206/416、HEAD。
- 前端视频播放器 + 基础时间轴。
- 测试：上传小视频、Range 206、越权 404、错误文件 422。

验收：

- 上传演示视频后能看到封面、时长、fps。
- `curl -H "Range: bytes=0-1023"` 返回 206 和 `Content-Range`。
- 500 MB 视频后续手工验收；服务端内存不随文件大小增长。
- 未授权的视频流返回 404。

### M3 · 任务发布、领取与释放

**目标**：管理员发布任务，标注员独占领取，能释放。

任务：

- 管理员创建任务（租户、视频、标题、描述）。
- 任务列表、任务详情。
- 标注员任务池：可领取 + 我的任务。
- 领取事务 + 部分唯一索引；重复领取 409。
- 释放：删除草稿、assignment 变 RELEASED、任务回 PUBLISHED。
- 可选：管理员标注员列表 + 重新分配未提交任务（旧 assignment RELEASED，草稿删除）。
- 测试：领取、并发领取、释放、重新分配、跨租户。

验收：

- 两个标注员同时领取，只有一个成功。
- 领取后任务从“可领取”消失，出现在“我的任务”。
- 释放后任务回到任务池，草稿被清空。
- 重新分配后旧标注员看不到草稿，新标注员从空草稿开始。
- 其他租户看不到该任务。

### M4 · 片段草稿、校验、提交与统计

**目标**：核心业务规则闭环。

任务：

- 领域函数：`validate_segments`、`sum_duration`、`business_day`。
- `PUT /draft` 全量替换 + 版本号；草稿自动保存。
- `POST /submit`：校验、快照总时长、写 `submitted_at`、锁定。
- 空提交 `confirm_empty`。
- `GET /api/admin/stats/daily`：时区归日、补零、按租户过滤。
- 测试：首尾相接、部分重叠、包含、相同、零长度、超边界、草稿不计、提交日边界、重复提交。

验收：

- 首尾相接允许；真正重叠返回 422 `OVERLAP`。
- 草稿保存后刷新仍在；未提交统计为 0。
- 提交后总时长正确，重复提交 409。
- 23:59 和 00:01 提交分别归到两天（Asia/Shanghai）。
- 另一个租户的统计看不到这些数据。

### M5 · 标注工作台

**目标**：标注员每天能高效使用。

任务：

- 登录页、任务列表页、工作台路由。
- 工作台布局：视频、时间轴、片段列表、提交区。
- 时间轴：刻度、播放头、拖拽创建、拖两端调整、拖中间移动。
- 键盘：空格、I/O、方向键、Delete、Ctrl+Z、Ctrl+S、Ctrl+Enter。
- 片段列表：起止时间可编辑、跳转、删除、时长。
- 重叠即时提示；冲突高亮；保存状态；离开提示。
- 空状态、加载骨架、错误提示、提交确认、只读状态。
- 草稿自动保存 + 版本冲突处理。

验收：

- 不用鼠标也能完成“播放、打点、调整、保存、提交”。
- 制造重叠时，前端阻止并给出明确提示。
- 刷新页面草稿不丢；提交后刷新只读。
- 空提交会二次确认。
- 1280px 宽度下布局不溢出；1024px 可用。

### M6 · 管理端与统计

**目标**：管理员能看到任务、片段和每日时长。

任务：

- 视频库：上传、列表、封面、时长、编码。
- 任务列表：状态、租户、领取人、提交时间、总时长。
- 任务详情：视频预览、已提交片段列表/时间轴、总时长、提交时间。
- 统计页：日期范围、租户选择（平台管理员）、柱状图、表格、时区说明、补零。
- 平台管理员租户切换。
- 可选：按标注员 breakdown、CSV 导出。

验收：

- 管理员能看到每个已提交任务的片段列表（输出要求 1）。
- 统计页能看到每天的有效时长（输出要求 2）。
- 平台管理员切换租户后，数据随之变化。
- 租户管理员看不到其他租户。
- 无数据时有空状态，不是空白页。

### M7 · 完整打磨与交付

**目标**：可演示、可复现、可评审。

任务：

- Playwright E2E：登录、领取、标注、提交、管理员查看、跨租户。
- 500 MB ALOHA 视频上传、播放、拖动、跳转、内存观察。
- 视觉打磨：间距、字号、颜色、按钮状态、Toast、Modal、骨架屏。
- 可访问性：焦点、label、键盘、对比度。
- README：从零启动、演示账号、测试命令、已知限制、截图、数据集来源与 MIT 许可。
- `report.md`：决策、验证证据、rules/skills、未完成项。
- 代码清理：无用依赖、死代码、日志、错误信息。
- 整理 git 提交历史；准备个人仓库链接（未确认前不 push）。
- 可选：截图/GIF/2 分钟演示视频。

验收：

- 按 README 从零启动成功。
- 5 分钟演示路径完整走通。
- 所有单测、集成测试、E2E 通过。
- 500 MB 视频可用；Safari/AV1 限制写清楚。
- `report.md` 有具体测试证据，不是空话。
- 没有已知的阻塞性缺陷。

## 3. 依赖关系

```text
M0 ──▶ M1 ──▶ M2 ──▶ M5 ──▶ M7
          │      │
          └──▶ M3 ──▶ M4 ──▶ M6 ──▶ M7
```

- M1 是基础，不能跳过。
- M2 和 M3 可以并行，但 M5 需要两者都完成。
- M4 的统计接口可以先于前端完成，用 API 测试验收。
- M6 可以在 M5 之后并行做，但依赖 M4 的统计数据。
- M7 最后统一收口。

## 4. 完成定义（Definition of Done）

一个功能只有同时满足以下条件才算完成：

- 代码实现，且有明确的错误处理。
- 至少一个自动化测试，覆盖 happy path 和关键边界。
- 租户/角色校验已加，跨租户测试通过。
- 前端有 loading / empty / error 状态。
- API 契约更新到 `02-architecture.md`。
- 手工验收通过，记录在 `05-ai-collaboration.md` 的验证日志。
- 没有新增已知阻塞问题；有已知限制就写进 report。

## 5. 演示脚本

用于评审和自测，按顺序执行：

1. `docker compose up --build`；打开 `http://localhost:8080`。
2. 用标注员 A1 登录：
   - 看到 Alpha 租户的可领取任务。
   - 领取“咖啡演示片段标注”。
   - 播放视频，拖出两段；尝试让第二段与第一段重叠，被阻止。
   - 用键盘 `I` / `O` 再标一段；保存。
   - 提交；看到总时长。
3. 刷新页面：任务只读，片段仍在。
4. 用租户管理员 A 登录：
   - 任务详情能看到刚提交的片段列表和总时长。
   - 统计页能看到当天有效时长。
5. 用标注员 B1 登录：
   - 看不到 Alpha 租户的任务；直接访问 A 的任务/视频 URL 返回 404。
6. 用平台管理员登录：
   - 切换 Alpha/Beta 租户，分别看到两边数据。
7. 打开 `report.md`，展示决策和验证证据。

## 6. 风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| 500 MB 上传/播放卡顿 | 演示失败 | 流式上传、Range、faststart；提前用 ALOHA 实测；nginx 关闭请求缓冲 |
| AV1 在 Safari 黑屏 | 评审环境不可用 | README 推荐 Chrome/Edge；提供 H.264 转码开关；提前测试 |
| ffmpeg 不在评审环境 | 上传失败 | Docker 镜像内置 ffmpeg；README 写本机依赖 |
| 时间轴交互复杂 | 拖拽/缩放出 bug | 先做“点击创建 + 拖动调整”最小版，再加拖拽创建；用指针事件和边界测试 |
| 草稿保存冲突 | 数据覆盖 | 版本号乐观锁；冲突时提示刷新；自动保存防抖 |
| 领取并发 | 两人同时领取 | `SELECT FOR UPDATE` + 部分唯一索引 + 409 |
| 统计时区错误 | 数字对不上 | 固定 `Asia/Shanghai`，单测 23:59/00:01；页面标注时区 |
| 测试数据库污染 | 测试互相影响 | 独立 test database；每个测试事务回滚或 truncate |
| Docker 构建慢 | 开发效率低 | 本地 dev 优先；镜像分层；依赖缓存 |
| 范围蔓延 | 核心做不完 | 严格按 `00-overview.md` 的“本期不做”清单拒绝新需求 |

## 7. 范围守卫

开发中如果有人提议以下功能，先记录到“以后再做”，不进入本期：

- 评论、@提醒、标签分类。
- AI 自动分段、模型推理。
- 多人同时标注同一个任务。
- 任务提交后的退回/重开。
- 自助注册、找回密码、用户管理后台。
- URL 导入视频、对象存储、CDN。
- 移动端专门适配。
- 实时协作、WebSocket。
- 复杂权限（自定义角色、细粒度 ACL）。
