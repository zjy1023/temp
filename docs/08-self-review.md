## 2. 自审发现的缺口与修正

| 缺口 | 风险 | 修正 |
|---|---|---|
| 只有 UX 零散描述，没有页面级规格 | 视觉计分项靠临场发挥 | 新增 `06-ui-spec.md`：布局、时间轴、键盘、状态、视觉 token |
| API 只有端点表，没有完整请求/响应 | 前后端各写一套，联调返工 | 新增 `07-api-contract.md`：每个接口的字段、校验、错误码 |
| 任务和视频可能跨租户 | A 租户视频挂到 B 租户任务，隔离漏洞 | D24 + 02 §4.4 + 04 测试 |
| 草稿全量重建会丢 ID | 自动保存后选中态/焦点跳动 | D25 + 07 §5 + 04 测试 |
| VFR/未知帧率没有定义 | 按固定帧长吸附会标错位置 | D27 + 03 M2 + 04 手工验收 |

## 3. 仍然无法消除的不确定性

这些不是文档漏洞，而是环境/评审侧的不确定：

1. **评分权重未公开**。交付按需求覆盖、领域规则、UX、验证证据四块组织，确保每块都有可检查的结果。
2. **浏览器兼容性**。AV1 播放依赖浏览器与系统解码能力；推荐 Chrome/Edge/Firefox，并提供 `TRANSCODE_TO_H264` 开关。
3. **大文件上传**。流式写盘 + Nginx 关闭请求缓冲；已用 500 MB 样本验证上传、播放与跳转。
4. **首屏演示**。seed 自带合成视频，无需上传即可走完整流程。
5. **一人独占领取**是产品决策，备选方案与理由见 `01-decisions.md`。
6. **运行环境**。Docker、ffmpeg、PostgreSQL 已在当前机器验证；镜像拉取受限时按 README 配置镜像加速。

## 4. 设计取舍复核

| 取舍 | 是否值得 | 说明 |
|---|---|---|
| 平台管理员 + 租户管理员 | 值得 | 多一层角色，但能真正演示“发布任务时指定租户”和跨租户隔离 |
| 一人独占领取 | 值得 | 与“每个已提交任务的时间段列表”最一致；并发和统计都简单 |
| 空提交允许 | 值得 | 真实标注可能没有有效片段；显式确认避免误操作 |
| 提交锁定 | 值得 | 统计稳定；退回/重开作为已知限制 |
| 不做分页 | 值得 | 本期数据量小；避免前端分页状态 |
| 默认不转码 H.264 | 值得 | 500 MB 转码拖慢演示；README + 开关兜底 |
| 只做本地上传 | 值得 | 避免 SSRF、外部链接失效；真实视频由使用者下载 |
| 不做评论/AI 分段/实时协作 | 值得 | 不挤占核心规则和 UX |

## 5. 开工结论

- 显式需求全部覆盖。
- 自审发现的 17 个缺口已写入文档或测试计划。
- 剩余风险是环境/评审侧，已有兜底方案，不需要再改架构。
- **可以开始 M0**。

M0 的边界：目录、依赖、Docker Compose、后端 health、前端壳、演示视频、README 初稿。M0 不写业务逻辑，先把“从零启动”跑通。
